# Virtual environments and dependency management

Dependency management has exactly one goal: to turn "it runs on my machine" into "it runs on anyone's machine, anywhere". The tools are the venv + pip + lock-file trio, with modern tools uv/Poetry adding speed.

## venv isolation

One virtual environment per project, so they don't pollute each other (creation and activation are covered in the setup chapter). The two facts that matter here are the ones tied directly to dependency management:

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install requests
python3 -m pip list
```

```text
Package    Version
---------- -------
requests   2.x.x
```

- `.venv/` is an ordinary directory; delete it to reset, and `python3 -m venv .venv` rebuilds it.
- A venv should not go into version control (.gitignore already ignores it); reproducibility comes from the lock file below.

## requirements.txt: locking dependencies

The two file types have different jobs: a hand-written list of direct dependencies with loose constraints, and a full lock file (generated by `pip freeze`, exact versions). A project usually wants both:

```bash
python3 -m pip freeze > requirements.lock   # Full exact lock, transitive dependencies included
```

For hand-written direct dependencies, give both a lower and an upper bound to avoid an accidental major-version upgrade:

```text
# requirements.txt（直接依赖）
requests>=2.31,<3
rich>=13
```

Installing and checking:

```bash
python3 -m pip install -r requirements.txt
python3 -m pip check        # Check for dependency conflicts
python3 -m pip list --outdated   # See which packages can be upgraded
```

::: tip Why pip freeze isn't good enough
freeze pins every transitive dependency, and across platforms the platform-specific packages contaminate each other; upgrading a single package means re-locking the whole file. Modern options: `uv pip compile` (generates a lock file from pyproject.toml and distinguishes direct from transitive dependencies) or Poetry's `poetry.lock` (with hash verification).
:::

## pyproject.toml: the project's single source of truth

PEP 621 standardizes project metadata: dependencies, version, build backend — all in one file. pip 19+ can install straight from pyproject.toml:

```toml
# pyproject.toml
[project]
name = "hello-python-demo"
version = "0.1.0"
requires-python = ">=3.10"
dependencies = [
    "requests>=2.31,<3",
]

[project.optional-dependencies]
dev = ["pytest>=8", "ruff>=0.6"]

[build-system]
requires = ["setuptools>=75"]
build-backend = "setuptools.build_meta"
```

```bash
python3 -m pip install -e ".[dev]"   # Editable install plus dev dependencies
```

## uv / Poetry / PDM

| Tool | Positioning | One-liner |
| --- | --- | --- |
| `uv` | Rust implementation, pip-ecosystem compatible | 10-100x faster, first pick for new projects |
| `Poetry` | Dependencies and packaging in one | A mature lock-file experience with its own config system |
| `PDM` | PEP 582/621 pioneer | The optional route that skips virtual environments |
| `pip-tools` | A patch on the pip ecosystem | requirements.in -> lock.txt |

uv's typical workflow (speed is its biggest argument):

```bash
uv venv                 # Create the virtual environment
uv pip install -r requirements.txt
uv add requests         # Or project mode: uv init && uv add requests
uv lock                 # Generate uv.lock, reproducible across machines
```

## Multiple Python versions

- `pyenv`: user-level multi-version, `pyenv local 3.12` writes .python-version.
- Official installers/Docker: images pin a version for CI and production (`python:3.12-slim`).
- A virtual environment is bound to the interpreter that created it; changing version means rebuilding.

## A list of common accidents

- Installing into the global pip -> a system tool's dependency gets upgraded and breaks (Linux distros are especially sensitive; PEP 668 forbids it by default, and `--break-system-packages` is the bypass — don't bypass it, use a venv).
- A requirements.txt that's written but never locked -> the "it worked fine last week" kind of drift.
- Committing .venv into the repo -> size explosion plus platform-incompatible binaries.
- A lock file out of sync with pyproject.toml -> CI installs something different from local.

## Summary

- venv isolates the environment, pyproject.toml declares direct dependencies, the lock file fixes the full version set.
- `python3 -m pip` points at the pip of the current interpreter.
- Reach for uv if you want speed, Poetry if you want a mature lock experience; pip freeze is the floor, not the destination.
- About nine-tenths of accidents come from "not isolating" and "not locking versions".
